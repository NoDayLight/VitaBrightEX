# VitaBrightEX pseudo-v1.4 architecture

Pseudo-v1.4 treats brightness control as the core product and every less-established display mutation as an optional capability. The correct failure mode is loss of an enhancement, never loss of LiveArea.

## Vertical contract

The production path is intentionally one coherent stack:

```text
filesystem source
    -> open-result classification
    -> authority decision
    -> production streaming parser
    -> validated candidate
    -> transactional subsystem operation
    -> subsystem-owned error domain
    -> rollback/recovery if needed
    -> capability/status state
    -> derived legacy last_error
    -> diagnostics ABI
    -> matching editor
    -> CI exercising the same production-shared cores
```

No layer is allowed to reinterpret another layer's failure. No Python-only grammar or test-only semantic shadow is accepted as proof.

## Boot and serialization contract

`module_start()` reads firmware/model once, initializes status and the state-transition mutex, initializes safe config defaults, attempts authoritative config load, starts exactly one brightness backend, probes optional verified capabilities, and always fails open at the module boundary.

One kernel mutex serializes reload/editor/status transitions. User writes follow:

`checked user copy -> temporary candidate -> validation -> state lock -> transactional change -> commit/rollback`

Hook callbacks do not take the mutex. No polling thread, timer, periodic file read, framebuffer interception, per-frame callback or software pixel-processing path is introduced.

## Authoritative source selection

Authority is defined by `source_authority.c` / `source_authority.h` and documented in [`SOURCE-AUTHORITY.md`](SOURCE-AUTHORITY.md).

Only an explicit file-not-found result from the **OPEN stage** permits fallback. The production classifier uses VitaSDK's `SCE_ERROR_ERRNO_ENOENT`; no guessed numeric file-not-found constant is used.

```text
OPEN succeeds
    -> source becomes authoritative
    -> READ/PARSE/CLOSE failure is terminal

OPEN returns ENOENT
    -> source is absent
    -> documented fallback may be attempted

OPEN returns any other failure
    -> terminal source I/O failure
```

A later read/parse/close failure cannot become fallback-eligible even if its raw integer happens to equal ENOENT. Fallback is a classified source outcome, not raw-error equality.

Config order is `ur0 -> ux0 -> compiled defaults`, where defaults are selected only if both files are explicitly absent. LCD LUT order is `ur0 -> ux0 -> compiled safe table`, again only on explicit absence. OLED panel/generic search advances only on explicit absence; an explicit `panel_lut_path` is one source and never falls back.

## Production parser contract

All authoritative text parsers share `text_stream.c`:

- LF accepted;
- CRLF accepted;
- CR followed by non-LF rejected;
- terminal lone CR rejected;
- CR is never deleted from inside a token.

LCD is exactly 17 unsigned decimal bytes in monotonic nondecreasing order. OLED is exactly 17 rows × 21 two-digit hex bytes. Full-line comments are streamed without a fixed physical-line buffer.

`config_parser.c` is the production parser core. Known numerics require complete tokens; suffix garbage is rejected; extreme values saturate safely then clamp. Unknown keys and missing-`=` lines remain compatibility no-ops. Empty numeric values fail; empty `panel_lut_path` is valid. Duplicate known keys use last-valid textual occurrence. `display_color_space_mode` and `lcd_color_space_mode` are compatibility aliases for the same field and follow the same last-valid-occurrence rule.

Config is parsed into a temporary candidate and committed atomically. Failed config input never partially mutates the currently committed `g_config`.

## LCD brightness transaction

PCH-2000 startup acquires:

1. validated authoritative LUT candidate;
2. required SceLcd exports by NID;
3. whitelisted firmware layout candidate;
4. exact runtime stock-signature validation at the inherited segment-0 address;
5. table injection;
6. brightness hook;
7. ScePower maximum-brightness hook;
8. checked current-brightness reapply;
9. active-state commit.

Raw candidates remain 3.60 -> `0x1B00` and 3.65/3.67/3.68/3.69/3.70 -> `0x1B48`. 3.71–3.74 are not guessed to share that layout.

The default extended table remains:

```text
1 3 5 8 13 20 29 41 57 76 95 116 137 161 190 220 255
```

The inactivity hook intervenes only on firmware request `brightness==1`; it suppresses the dim request only when the currently indexed extended value is below 25, avoiding paradoxical brightening.

## OLED brightness transaction

PCH-1000 startup requires a whitelisted firmware family, resolves brightness/DDB exports, requires successful DDB, maps the panel to the inherited upstream offsets, validates the loaded-module table location, loads a complete 17×21 candidate, injects it, installs brightness/power hooks, reapplies current brightness, and commits only after all required stages succeed.

DDB low byte 4 -> `0x1AB8`, 5 -> `0x1C20`, and 6/other successfully read types -> `0x1E00`. A failed DDB read never becomes an assumed default panel.

OLED bytes remain opaque panel-control data. Pseudo-v1.4 does not reintroduce guessed white-point, RGB-bias or night-mode arithmetic.

## Transaction teardown and rollback

LCD/OLED replacement retains the previous committed table. Before replacement, taiHEN resources are released transactionally. Release return values are checked; a handle is invalidated only after confirmed release.

If teardown is incomplete, the backend records `VBE_ERR_RESOURCE_RELEASE`, marks the transaction degraded/failed and refuses to initialize a new stack over uncertain ownership.

If a requested replacement fails after clean teardown, the previous table is reinstalled where possible. Rollback uses the authoritative BRIGHTNESS-domain state directly, never the compatibility `last_error` summary.

- replacement fails + rollback succeeds: previous backend returns operational/active, while the requested operation's BRIGHTNESS failure remains visible;
- replacement fails + rollback fails: BRIGHTNESS becomes `VBE_ERR_LUT_ROLLBACK` and capability state stays degraded rather than falsely active.

## Error ownership and reload lifecycle

Detailed policy is in [`DIAGNOSTICS-ERROR-MODEL.md`](DIAGNOSTICS-ERROR-MODEL.md).

Per-domain slots are authoritative internal state:

- SYNC: state-transition lock;
- CONFIG: `config_load()`;
- BRIGHTNESS: LCD/OLED load, transaction, persistence and recovery;
- COLOR_SPACE: panel color-space operations;
- FILTER: verified filter runtime operation;
- INPUT: user-facing argument validity.

Each subsystem clears only the domain it repaired. Generic reload no longer clears CONFIG+BRIGHTNESS based on one composite result. A repaired config therefore clears CONFIG immediately even if the later LUT transaction fails; a successful brightness replacement cannot erase a still-broken config.

The outer reload orchestrator combines stage return values for caller control flow, but it does not guess diagnostic ownership.

`VitaBrightStatus` remains ABI v2 with unchanged layout. `last_error/detail` is derived compatibility state only. Its fixed precedence is:

```text
SYNC > BRIGHTNESS > CONFIG > COLOR_SPACE > FILTER > INPUT
```

`VitaBrightDiagnostics` ABI v1 exposes the full domain state additively.

## Unsupported filter semantics

Hardware invert remains the only verified generic screen-filter mutation. Advanced CCT/gamma/contrast/brightness/panel-enhance requests are explicit unsupported capability requests.

`VBE_RESULT_UNSUPPORTED` is a positive nonzero capability result; negative values remain actual runtime/SCE/taiHEN failures. Unsupported advanced requests keep CSC/transfer capability state `UNSUPPORTED`, leave FILTER diagnostics clear, make no speculative hardware write and are reported by the editor as unsupported rather than generic failure.

The private v1.3 `0x0FCBF457` path remains removed. VitaSDK's documented `ksceIftuCsc()` does not establish a persistent active-scanout matrix setter.

## Panel color-space capability

Matched panel Get/SetDisplayColorSpaceMode exports are session-scoped. Pseudo-v1.4 snapshots original mode, accepts only 0/1, avoids redundant writes, performs immediate read-back verification and restores firmware-owned state on teardown. Config-driven color-space application does not own or clear INPUT diagnostics; only the user syscall path does.

## Authoritative persistence

The backend records the exact path associated with the committed LUT. Save writes a same-directory temporary file, syncs/closes it, then renames it over the authoritative target. Editor code never guesses OLED panel or ur0/ux0 filenames.

## CI proof

`tools/validate_packaged_assets.py` byte-compares packaged assets and compiles/runs production-shared host regressions for:

- LUT parsing;
- config parsing;
- source authority;
- error lifecycle/precedence/recovery;
- unsupported filter capability policy.

`tools/verify_source_contract.py` and `tools/verify_parser_contract.py` are structural tripwires only. They additionally forbid backends from reading legacy `last_error/detail` as internal state, forbid config lifecycle ownership inside brightness backends, and guard checked taiHEN resource-release handling.

Release and diagnostic SKPRX builds, generated stubs, matching editor and PCH-2000 bundle build under current VitaSDK with warnings treated as errors. Final CI reports branch-exact payload SHA-256 values.
