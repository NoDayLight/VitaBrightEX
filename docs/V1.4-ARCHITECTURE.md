# VitaBrightEX pseudo-v1.4 architecture

Pseudo-v1.4 treats brightness control as the core product and every less-established display mutation as an optional capability. Correct failure mode is loss of an enhancement, never loss of LiveArea.

## Boot contract

`module_start()`:

1. reads firmware and detects panel family once
2. initializes the capability/status object
3. creates the global state-transition mutex
4. loads configuration as defaults → candidate → validate → commit
5. starts exactly one brightness backend transaction
6. probes/applies optional verified capabilities
7. returns `SCE_KERNEL_START_SUCCESS` even when a backend/enhancement is unavailable

No polling thread, timer, periodic file read, framebuffer interception, per-frame callback or software pixel-processing path is introduced.

## Serialization model

One kernel mutex serializes reload/editor/status state transitions. User writes follow:

`user pointer → checked copy to temporary kernel object → structural/range validation → acquire state lock → transactional hardware change → commit/rollback`

Hook callbacks do not take the mutex. That avoids introducing work into the normal brightness hook path and avoids a hook/mutation lock inversion. Teardown removes hooks before invalidating the state/function pointers a hook may observe.

## LCD brightness transaction

PCH-2000 startup acquires:

1. required `SceLcd` exports by NID
2. firmware whitelist/layout candidate
3. runtime verification of the stock brightness-table signature at the inherited offset
4. 17-byte table injection
5. brightness hook
6. ScePower maximum-brightness hook
7. one current-brightness reapply
8. active-state commit

Any failure unwinds acquired resources. A live LUT replacement preserves the last committed table and attempts rollback if the new transaction fails.

### Raw-layout policy

The only inherited layouts kept are those present in original VitaBright:

- 3.60 → `0x1B00`
- 3.65 / 3.67 / 3.68 / 3.69 / 3.70 → `0x1B48`

3.71–3.74 are not inferred to share `0x1B48`. GitHub-wide source review found no independent corroboration for the VitaBrightEX extension of that offset.

Even on a whitelisted version the loaded module must contain the original 17-byte stock table signature before v1.4 injects. This converts the inherited offset from a blind patch into an offset + runtime-layout check and also fails open on conflicting pre-patches.

## OLED brightness transaction

PCH-1000 startup:

1. requires a whitelisted raw layout (3.60/3.65/3.67/3.68/3.69/3.70)
2. resolves `SceOled` brightness + DDB exports by NID
3. requires a successful DDB read
4. derives the upstream panel table mapping from the DDB result
5. loads a complete 17×21-byte candidate LUT
6. rejects obviously corrupt all-zero/all-FF candidates while otherwise treating bytes as opaque
7. injects the candidate
8. installs brightness hook
9. installs ScePower hook
10. reapplies current brightness once
11. commits LUT/panel/status only after the transaction succeeds

Panel mapping is the mapping introduced by the upstream maintainer fix in VitaBright PR #39:

- low DDB byte 4 → `0x1AB8`
- low DDB byte 5 → `0x1C20`
- other *successfully read* DDB types → `0x1E00`

The important v1.4 change is that DDB failure is not treated as the default panel type.

### OLED LUT semantics

The table is panel control/calibration data, not a documented linear RGB framebuffer LUT. Therefore v1.4 removed automatic white-point arithmetic, byte-level RGB bias and night-mode transforms. Raw panel-specific LUTs and explicitly edited LUT bytes remain supported.

Live LUT replacement preserves the previous committed table and attempts rollback if reinjection/hook setup fails.

## Configuration

Every load begins from a constant default configuration, parses into a temporary candidate, validates/clamps it, then publishes one snapshot. Removing a key restores its default after reload.

Precedence is `ur0:tai/vitabrightex.cfg`, then `ux0:tai/vitabrightex.cfg` only when the primary file cannot be opened.

Optional colour mutations default off. Legacy keys remain parseable for compatibility but are not allowed to imply a processing stage that no longer exists.

## Screen-filter capability boundary

The v1.3 private `0x0FCBF457` call is gone.

Current VitaSDK defines `SceIftuCscParams` as a 0x3C-byte structure with an S3.9 matrix and exposes `ksceIftuCsc(SceIftuFrameBuf *, SceIftuPlaneState *, SceIftuConvParams *)` under NID `0x67E37EFC`. That is an explicit source/destination conversion API, not evidence of a persistent active-scanout matrix setter.

Consequently:

- verified generic hardware invert: supported when the SceDisplay export resolves
- persistent LCD CCT/contrast/brightness CSC: unsupported
- gamma correction: unsupported
- nonlinear panel linearisation: unsupported

A 3×3 linear matrix must not be relabelled as nonlinear gamma/linearisation.

## LCD colour-space handling

The NID-verified live `SceLcd` color-space function remains an optional session-scoped capability and defaults off. v1.4 does not perform persistent registry writes. Legacy “saturation boost / IPS enhance” names do not constitute distinct processing engines.

## Status ABI v2

`vitabrightGetStatus()` reports:

- hardware and firmware
- OLED panel type
- state-lock state
- firmware-layout state
- brightness core/table/hook/power-hook state
- invert and LCD color-space capabilities
- CSC/transfer-LUT support state
- last error and detail

The status snapshot itself is serialized. The editor must use this object instead of inferring support from model type.

## Source-controlled companion editor

Historical v3/v4 editor commits contain VPK binaries but no source. v1.4 adds a new editor source tree and builds it in CI against the generated syscall stubs. Unsupported controls are absent/disabled by capability rather than silently doing nothing.

## Build verification

`.github/workflows/build.yml` bootstraps current VitaSDK through current `vitasdk/vdpm`, builds the kernel plugin/stubs and builds the companion editor. Build success is a compiler/linker verification only; it is not a substitute for physical kernel/display testing.

## Remaining release gate

Code-side architecture/hardening is expected to be validated by CI and review, but the PR stays draft until physical tests in [`HARDWARE-TEST-MATRIX.md`](HARDWARE-TEST-MATRIX.md) pass. The first mandatory target is the reproducing PCH-2000 / 3.65 Ensō console.

Reverse engineering of a true persistent active-scanout CSC/nonlinear transfer path may continue independently; its absence does not block a safe brightness-focused v1.4.
