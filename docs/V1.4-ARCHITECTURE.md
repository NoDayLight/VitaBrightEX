# VitaBrightEX pseudo-v1.4 architecture

Pseudo-v1.4 treats brightness control as the core product and every less-established display mutation as an optional capability. The correct failure mode is loss of an enhancement, never loss of LiveArea.

## Boot contract

`module_start()`:

1. reads firmware and detects panel family once
2. initializes the capability/status object
3. creates the global state-transition mutex
4. loads configuration as defaults → candidate → validate → commit
5. starts exactly one brightness backend transaction
6. probes/applies optional verified capabilities
7. returns `SCE_KERNEL_START_SUCCESS` even when a backend/enhancement is unavailable

No polling thread, timer, periodic file read, framebuffer interception, per-frame callback or software pixel-processing path is introduced.

## Serialization model

One kernel mutex serializes reload/editor/status state transitions. User writes follow:

`user pointer → checked copy to temporary kernel object → structural/range validation → acquire state lock → transactional hardware change → commit/rollback`

Hook callbacks do not take the mutex. That avoids work in the normal hook path and avoids a hook/mutation lock inversion. Teardown removes hooks before invalidating state/function pointers a hook may observe.

## LCD brightness transaction

PCH-2000 startup acquires:

1. required `SceLcd` exports by NID
2. firmware whitelist/layout candidate
3. runtime verification of the exact stock 17-byte brightness-table signature at the inherited segment-0 offset
4. validated 17-byte table injection
5. brightness hook
6. ScePower maximum-brightness hook
7. one checked current-brightness reapply
8. active-state commit

Any failure unwinds acquired resources. Negative getter results are never cast into unsigned hardware writes. A live LUT replacement preserves the last committed table and attempts rollback if the new transaction fails.

The LCD file/parser/editor representation is monotonic nondecreasing in the driver's logical brightness direction. The source-controlled and packaged default assets are gated by CI against the same rule.

### Raw-layout policy

The only inherited layouts kept are those present in original VitaBright:

- 3.60 → `0x1B00`
- 3.65 / 3.67 / 3.68 / 3.69 / 3.70 → `0x1B48`

3.71–3.74 are not inferred to share `0x1B48`. Even on a whitelisted version, the loaded module must contain the exact original stock signature before v1.4 injects. This converts the inherited offset from a blind patch into an offset + runtime-layout check and also fails open on conflicting pre-patches.

Static decrypted-binary provenance is tracked separately in [`FIRMWARE-LAYOUT-VERIFICATION.md`](FIRMWARE-LAYOUT-VERIFICATION.md). A repository tool maps segment-relative offsets correctly for decrypted ELF input and refuses to call an encrypted SELF verification.

## OLED brightness transaction

PCH-1000 startup:

1. requires a whitelisted raw layout (3.60/3.65/3.67/3.68/3.69/3.70)
2. resolves `SceOled` brightness + DDB exports by NID
3. requires a successful DDB read
4. derives the upstream panel table mapping from the DDB result
5. resolves the inherited table address inside loaded `SceOled` and rejects an implausible 357-byte object
6. loads a complete 17×21-byte candidate LUT
7. rejects structurally corrupt candidates
8. injects the candidate
9. installs brightness hook
10. installs ScePower hook
11. obtains and reapplies the current brightness with checked signed return values
12. commits LUT/panel/source-path/status only after the transaction succeeds

Panel mapping preserves the upstream VitaBright DDB mapping:

- low DDB byte 4 → `0x1AB8`
- low DDB byte 5 → `0x1C20`
- low DDB byte 6 / other successfully read types → `0x1E00`

A failed DDB read is never treated as the default panel type. Live LUT replacement preserves the previous committed table and attempts rollback if reinjection/hook setup fails.

### OLED LUT semantics

The 21 bytes of a row are known to contain seven RGB gamma-reference triplets at panel grayscale reference points. What is *not* independently established is the display driver's per-reference register-code → physical-voltage/transfer function. Therefore v1.4 does not apply guessed arithmetic such as the old white-point normalization, byte-level RGB bias or night-mode transforms.

Panel-specific LUT files and explicit raw editor changes remain supported. This is a verification boundary, not a decision to remove functionality merely because implementation is difficult.

## Authoritative LUT loading and persistence

LUT state has one authority at a time.

- Missing preferred files may fall through to the documented fallback.
- An existing but malformed authoritative file is an error; it is not silently hidden by another file.
- The backend records the exact source path that produced the committed live table.
- Editor RAM changes go through checked kernel syscalls and transactional reinjection.
- Save goes through a kernel persistence syscall, not direct editor filesystem guesses.
- Persistence writes a temporary file in the same location, syncs it, closes it and renames it over the authoritative target only after the write succeeds.

This keeps custom OLED override paths and `ur0`/`ux0` fallback semantics aligned across edit → save → reload.

## Configuration

Every load begins from a constant default configuration, parses into a temporary candidate, validates/clamps it, then publishes one snapshot. Removing a key restores its default after reload.

Precedence is `ur0:tai/vitabrightex.cfg`, then `ux0:tai/vitabrightex.cfg` only when the primary file cannot be opened.

Optional colour mutations default off. Legacy keys remain parseable for compatibility but are not allowed to imply a processing stage that does not exist.

## Screen-filter capability boundary

The v1.3 private `0x0FCBF457` call is gone.

Current VitaSDK defines `SceIftuCscParams` as a 0x3C-byte structure with an S3.9 matrix and exposes `ksceIftuCsc(SceIftuFrameBuf *, SceIftuPlaneState *, SceIftuConvParams *)` under NID `0x67E37EFC`. That is an explicit source/destination conversion API, not evidence of a persistent active-scanout matrix setter.

Consequently:

- verified generic hardware invert: supported when the SceDisplay export resolves
- persistent LCD CCT/contrast/brightness CSC: unsupported
- gamma correction: unsupported
- nonlinear panel linearisation: unsupported
- direct OLED gamma-register arithmetic: unsupported without a verified register transfer model

A 3×3 linear matrix must not be relabelled as nonlinear gamma/linearisation.

Filter setting is all-or-nothing: a request containing unsupported dimensions is rejected instead of applying its supported invert bit as a partial side effect.

## Panel color-space capability

Both panel families expose matched Get/SetDisplayColorSpaceMode functions with independently named VitaSDK NIDs. v1.4 therefore implements one backend-neutral, session-scoped capability:

1. resolve the matching getter and setter for the selected panel backend
2. snapshot the firmware-owned original mode
3. permit only defined modes 0/1
4. skip redundant writes
5. set the requested mode
6. immediately read it back and require the expected value
7. restore the original mode during plugin teardown

This capability is available on OLED and LCD when those exports resolve. It performs no registry mutation and creates no continuous workload. Legacy `lcd_saturation_boost` / `lcd_ips_enhance` names can request this same verified capability but are not separate processing engines.

`rgb_range_mode` is not mutated: independent registry documentation identifies it as a PSTV-oriented setting with semantics inconsistent with the old VitaBrightEX claim.

## Status ABI v2

`vitabrightGetStatus()` reports:

- hardware and firmware
- OLED panel type
- state-lock state
- firmware-layout state
- brightness core/table/hook/power-hook state
- hardware invert state
- panel color-space capability/state
- CSC/transfer-LUT support state
- registry API state
- last error and detail

The status snapshot itself is serialized. The editor uses this object instead of inferring support from model type.

## Source-controlled companion editor

Pseudo-v1.4 adds a source-controlled editor and builds it against generated syscall stubs in CI. It provides:

- capability/status/error display
- transactional OLED/LCD LUT editing
- kernel-authoritative atomic LUT persistence
- verified hardware invert
- read-back-verified panel color-space toggle
- reload/status refresh

Unsupported CCT/gamma/contrast/panel-curve controls are absent/disabled rather than silently approximated.

## Build and asset verification

`.github/workflows/build.yml`:

1. enforces architectural source invariants
2. validates every packaged OLED/LCD LUT and the packaged config against authoritative source assets
3. bootstraps current VitaSDK through `vitasdk/vdpm`
4. builds the release kernel plugin/stubs with warnings as errors
5. builds the diagnostic plugin from the same functional sources
6. installs generated syscall stubs
7. builds the companion editor
8. uploads plugin/editor build artifacts

Build success is compiler/linker/package verification only; it is not a substitute for physical kernel/display testing.

## Remaining release gate

After the software/CI gate is clean, the PR stays draft until physical tests in [`HARDWARE-TEST-MATRIX.md`](HARDWARE-TEST-MATRIX.md) pass. The first mandatory target is the reproducing PCH-2000 / 3.65 Ensō console.

Reverse engineering of a true persistent active-scanout CSC/nonlinear transfer path may continue independently; its absence does not justify reintroducing speculative kernel ABI calls and does not block the verified brightness/color-space feature set.
