# VitaBrightEX pseudo-v1.4 architecture

Pseudo-v1.4 treats brightness control as the core product and every less-established display mutation as an optional capability. The correct failure mode is loss of an enhancement, never loss of LiveArea.

## Boot contract

`module_start()` reads firmware/model once, initializes status and the state-transition mutex, loads configuration as defaults -> candidate -> validate -> commit, starts exactly one brightness backend, probes optional verified capabilities, and always fails open at the module boundary. A malformed authoritative config is now reported as `VBE_ERR_CONFIG`; safe initialized defaults remain in use rather than hiding the parse failure or blocking boot.

No polling thread, timer, periodic file read, framebuffer interception, per-frame callback or software pixel-processing path is introduced.

## Serialization model

One kernel mutex serializes reload/editor/status transitions. User writes follow:

`checked user copy -> temporary candidate -> validation -> state lock -> transactional hardware change -> commit/rollback`

Hook callbacks do not take the mutex. Teardown removes hooks before invalidating state/function pointers visible to them.

## Authoritative text-parser contract

Physical PCH-2000 testing exposed an important v1.4 defect in the previous software gate: the packaged LCD LUT contained descriptive comments longer than the kernel's `char line[64]`, while the Python CI validator ignored comments without that limit. Workflow #114 therefore declared an authoritative file valid that the exact production SKPRX rejected before SceLcd layout validation.

That parser/CI divergence is release-blocking and is fixed as a class, not by shortening comments:

- LCD and OLED LUT parsing now use portable streaming C state machines; there is no fixed physical-line buffer.
- Once a full-line `#` or `;` comment is recognized, its remaining bytes are discarded until newline without storage, so comment length is not an input limit.
- LCD data remains strict: exactly 17 unsigned decimal bytes, each `0..255`, monotonic nondecreasing, optional horizontal whitespace/inline comment, CRLF accepted, EOF without trailing newline accepted.
- OLED data remains strict: exactly 17 rows of exactly 21 two-digit hexadecimal bytes with controlled separators/comments.
- malformed existing authoritative `ur0` data remains an error; it does not silently fall through to `ux0`. Only a missing preferred source permits documented fallback.
- config parsing was audited for the same class. Arbitrarily long full-line comments are streamed away; an overlong non-comment directive is consumed as one physical line and rejected rather than having its tail misread as another directive.

CI no longer maintains a looser Python LUT grammar. `tools/validate_packaged_assets.py` compiles `tests/lut_parser_host.c` together with the **same `lcd/lut_parser.c` and `oled/lut_parser.c` sources linked into the SKPRX**, then feeds those parsers the exact source/package bytes and regression cases including 16-KiB comments, malformed long data, CRLF, EOF-without-newline, wrong counts, >255 and non-monotonic input. `tools/verify_parser_contract.py` additionally prevents fixed-line parsers or fallback-policy drift from silently returning.

## LCD brightness transaction

PCH-2000 startup acquires:

1. validated authoritative LUT candidate
2. required `SceLcd` exports by NID
3. firmware whitelist/layout candidate
4. runtime verification of the exact stock 17-byte table signature at the inherited segment-0 offset
5. table injection
6. brightness hook
7. ScePower maximum-brightness hook
8. checked current-brightness reapply
9. active-state commit

Any failure unwinds acquired resources. Negative getter results are never converted into unsigned hardware writes. A live LUT replacement preserves the last committed table and attempts rollback if the replacement transaction fails.

The LCD representation is monotonic nondecreasing in the driver's logical brightness direction. The default extended table is:

```text
1 3 5 8 13 20 29 41 57 76 95 116 137 161 190 220 255
```

### Raw-layout policy and physical evidence

Inherited candidates remain:

- 3.60 -> `0x1B00`
- 3.65 / 3.67 / 3.68 / 3.69 / 3.70 -> `0x1B48`

3.71-3.74 are not guessed to share this layout. Every accepted candidate must still contain the exact Sony stock signature before injection.

On 2026-09-12 the mandatory physical PCH-2000 / 3.65 Ensō target (`0x03650000`) passed that production runtime gate at segment-0 `0x1B48`: after removal of the separate parser blocker, status became `firmware_layout/core/table/brightness_hook/power_limit_hook=active` with `last_error=0`. Stock-vs-extended A/B testing also confirmed the ascending table direction and extended lower luminance.

This is **physical runtime exact-signature evidence**, not static decrypted-binary verification. Static ELF/segment evidence remains pending and is tracked separately in [`FIRMWARE-LAYOUT-VERIFICATION.md`](FIRMWARE-LAYOUT-VERIFICATION.md).

## LCD inactivity-dim path

The hook only intervenes when the OS requests brightness `1`. It reads current logical brightness, derives table index, and suppresses the request only when the corresponding extended table value is below `25`, preventing a nominal dim request from making an already-darker display brighter.

Physical testing has passed midpoint dimming and observed low-level behavior consistent with this rule. True maximum-slider behavior remains an explicit open observation. Diagnostic builds now log `[LCD:DIM]` with the old raw value, derived index/table value and allow decision, plus `[LCD:POWER]` maximum-brightness requests. Release builds compile `LOG(...)` to a statement-safe no-op.

## OLED brightness transaction

PCH-1000 startup requires a whitelisted firmware family, resolves brightness/DDB exports, requires successful DDB, selects the upstream panel mapping, validates the inherited loaded-module table address, loads a complete 17x21-byte candidate, injects it, installs brightness/power hooks, performs a checked current-brightness reapply and commits only after all required stages succeed.

Panel mapping remains:

- DDB low byte 4 -> `0x1AB8`
- DDB low byte 5 -> `0x1C20`
- DDB low byte 6 / other successfully read types -> `0x1E00`

A failed DDB read is never treated as a default panel. Live replacement preserves the previous table and attempts rollback.

### OLED LUT semantics

The 21 bytes of each row are seven RGB gamma-reference triplets. The display driver's register-code -> physical-voltage/transfer function is not independently established, so v1.4 does not reintroduce guessed white-point/RGB-bias/night-mode arithmetic. Panel-specific LUTs and explicit raw editor edits remain supported.

## Authoritative LUT persistence

LUT state has one authority at a time. The backend records the exact source path that produced the committed table. Editor changes go through checked kernel syscalls. Square Save calls a kernel persistence syscall, which writes a same-directory temporary file, syncs/closes it, then renames it over the authoritative target. This preserves custom OLED overrides and `ur0`/`ux0` source identity across edit -> save -> reload.

## Configuration

Every successful load begins from constant defaults, parses a temporary candidate, validates/clamps it, then publishes one snapshot. `ur0:tai/vitabrightex.cfg` is authoritative when present; `ux0` is considered only when the primary cannot be opened. Existing malformed authoritative configuration is reported rather than split/truncated or silently replaced.

## Screen-filter capability boundary

The v1.3 private `0x0FCBF457` call is gone. VitaSDK documents `ksceIftuCsc()` NID `0x67E37EFC` as an explicit source/destination conversion API, not evidence of a persistent active-scanout matrix setter.

Therefore hardware invert is supported when its SceDisplay export resolves, while arbitrary persistent CCT/contrast/brightness CSC, gamma/nonlinear transfer, and direct OLED gamma-register arithmetic remain unsupported without the corresponding verified hardware model. Filter setting is all-or-nothing: unsupported dimensions reject the request rather than partially applying invert.

## Panel color-space capability

Matched panel Get/SetDisplayColorSpaceMode exports provide one backend-neutral session capability. v1.4 snapshots original mode, accepts only 0/1, avoids redundant writes, performs write + immediate read-back verification, and restores firmware-owned state on teardown. There is no registry mutation or continuous workload.

## Status ABI v2 and editor

`vitabrightGetStatus()` reports hardware/firmware, OLED panel, lock/layout states, brightness core/table/hooks, invert, panel color-space, unsupported CSC/transfer states, registry capability and last error/detail.

The source-controlled editor consumes this status rather than inferring support. It offers transactional LUT editing, kernel-authoritative persistence, invert, read-back-verified panel color-space, reload/status refresh, and no fake unsupported controls. The LCD cursor is explicitly labelled **`LCD LUT entry X/16`**; it is not the current Vita system brightness slider position.
