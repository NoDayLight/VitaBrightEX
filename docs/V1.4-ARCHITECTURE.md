# VitaBrightEX pseudo-v1.4 architecture

This branch deliberately prioritises correctness and fail-open boot behaviour over v1.3 feature claims.

## Boot contract

`module_start()` must always return `SCE_KERNEL_START_SUCCESS` after basic module setup. A failure in brightness-table injection, hook installation, display colour capabilities, or configuration must disable that capability rather than prevent LiveArea from loading.

Startup is:

1. Read configuration into a temporary default-initialised candidate.
2. Validate and atomically publish the candidate.
3. Detect hardware once.
4. Select exactly one backend.
5. Start the brightness core transactionally.
6. Probe/apply optional display capabilities.
7. Return success regardless of optional capability failure.

There are no polling threads, timers, per-frame callbacks, framebuffer interception paths, or periodic filesystem reads.

## LCD brightness transaction

The PCH-2000 brightness core acquires resources in this order:

1. Resolve required SceLcd exports.
2. Whitelist the firmware layout.
3. Inject the 17-entry brightness table.
4. Install the SceLcd brightness hook.
5. Install the ScePower maximum-brightness hook.
6. Re-apply the current brightness once.
7. Mark the core active.

Failure before step 7 releases every resource already acquired. Unknown firmware does not receive a guessed table offset.

Known table layouts currently retained from the existing implementation:

- 3.60: `0x1B00`
- 3.65, 3.67-3.74: `0x1B48`

No default/fallback offset exists.

## Live LCD LUT editing

Editor input is copied into a temporary 17-byte object, checked for monotonicity, then committed. Reapplying the candidate does not call the disk LUT loader, so an editor update cannot overwrite itself with stale file contents.

Persistence remains a userland/editor responsibility.

## Configuration

Every load begins from `k_default_config`, parses into a temporary candidate, validates/clamps it, then performs one assignment to `g_config`. Deleting a key therefore restores its default on the next reload.

Precedence is `ur0:tai/vitabrightex.cfg`, with `ux0:tai/vitabrightex.cfg` used only when the ur0 file does not exist.

Optional LCD colour controls default off.

## Screen-filter capability boundary

The v1.3 private call to `0x0FCBF457` has been removed.

VitaSDK documents `SceIftuCscParams` as a 0x3C-byte structure whose matrix is S3.9 fixed point, and documents `ksceIftuCsc(SceIftuFrameBuf *, SceIftuPlaneState *, SceIftuConvParams *)` under NID `0x67E37EFC`. That operation is an explicit source/destination buffer conversion API. It does not establish that Vita exposes a persistent active-scanout CSC setter suitable for changing the display head once and leaving it programmed.

Therefore pseudo-v1.4 does not use IFTU for persistent filtering until that path is independently established.

Current verified generic filter capability:

- hardware colour invert: supported when the SceDisplay export resolves

Explicitly unavailable/unsupported for now:

- persistent LCD CCT/contrast/brightness CSC
- gamma correction
- nonlinear panel linearisation

Gamma and panel linearisation must not be approximated with a 3x3 linear matrix.

## LCD colour-space handling

The live SceLcd colour-space function remains an optional session-scoped capability. v1.4 does not write persistent display registry keys during boot. There is currently no verified session-scoped RGB-range implementation in this branch, so registry-based RGB-range mutation is not performed.

## Status ABI

`vitabrightGetStatus()` exposes the selected hardware, firmware, capability states, and last error/detail. Capability states distinguish inactive, active, unavailable, failed, and unsupported.

The editor should use status rather than infer support from model type or assume a syscall succeeded because the plugin loaded.

## Remaining hardening work before calling this a release

- Convert the OLED startup path to the same explicit transaction/result model as LCD.
- Harden OLED LUT editor input with copy/validate/commit semantics appropriate to panel-control bytes.
- Add locking around editor/reload state transitions if concurrent syscall entry is possible in practice.
- Update the companion editor to consume `vitabrightGetStatus()` and hide/disable unsupported controls.
- Build with VitaSDK and perform hardware regression tests on at least PCH-1000 and PCH-2000.
- Verify brightness-table offsets against the supported SceLcd binaries rather than relying only on inherited offsets.
- Continue reverse engineering the active scanout pipeline before reintroducing any persistent CSC/transfer-LUT feature.
