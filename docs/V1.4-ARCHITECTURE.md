# VitaBrightEX pseudo-v1.4 architecture

Pseudo-v1.4 is organized around one rule: hardware mutation is allowed only when state ownership is explicit enough to commit, roll back and unload safely. Optional enhancement failure is fail-open at boot; uncertain runtime ownership is fail-closed for further mutation.

## Runtime boundary

Startup initializes model/firmware, status and compiled-safe defaults before creating the global state-transition mutex. Successful mutex creation is the runtime-init commit point. Only then may config files be read or display/backend state be mutated. Failure before that point leaves an `INERT + ABSENT` module with no runtime teardown responsibility and still returns boot success.

Mutable user operations follow:

```text
checked user copy
-> candidate validation
-> global state lock
-> one subsystem transaction
-> commit/rollback
-> checked unlock
```

No polling thread, timer, framebuffer interception, per-frame callback or CPU-side pixel pipeline exists.

## Backend ownership

LCD and OLED share the production transaction vocabulary while retaining hardware-specific edges:

```text
CLEAN
    no backend taiHEN resource owned

ACTIVE
    one complete committed backend installed

DEGRADED
    retained or uncertain ownership;
    no new mutation and no rollback
```

Attempt outcomes are `TXN_OK`, `TXN_FAILED_CLEAN` and `TXN_FAILED_DIRTY`. A previous ACTIVE state may be rolled back only after a clean candidate failure and only while ownership is CLEAN. A failed resource release immediately makes ownership DEGRADED.

Teardown order remains dependency-aware:

```text
power hook -> brightness hook -> table injection
```

and stops at the first failed release. Handles are forgotten only after confirmed release.

## Multi-stage result composition

Reload stages use one production-shared scalar rule:

```text
negative runtime failure
>
positive capability/partial result
>
zero success
```

Thus an unsupported OLED/filter request cannot hide a later runtime failure. Detailed CONFIG/BRIGHTNESS/COLOR_SPACE/FILTER/INPUT/SYNC slots preserve the independent facts.

Unlock/release has stricter ownership semantics: a synchronization release failure dominates the scalar syscall result even if the operation also failed. The operation's domain error remains recorded separately.

## Source authority and config transaction

Only OPEN-stage explicit not-found permits fallback. Once OPEN succeeds, READ/PARSE/CLOSE failure is terminal. Config search order is `ur0 -> ux0 -> COMPILED`; LCD LUT search is `ur0 -> ux0 -> COMPILED`; OLED uses panel-specific FILE sources and then generic FILE sources, with no fabricated compiled OLED LUT.

Config now has the same explicit source identity model as LUT state:

```text
NONE
FILE + exact path
COMPILED + no path
```

Reload snapshots the committed config and source identity before parsing a new candidate. A candidate source is not allowed to survive a failed backend replacement. If candidate `FILE ur0:B` is followed by a clean backend failure and rollback, the previous config and `FILE ux0:A` identity are restored before the locked reload returns.

## LCD transaction

PCH-2000 installation requires a validated candidate, required exports, an accepted firmware/layout, the exact stock-table signature, table injection, brightness hook, power hook and checked current-brightness reapply before ACTIVE commit.

The 3.65 path uses segment 0 + `0x1B48`. Retail 3.65 static extraction and the physical 3.65 console independently contain the exact stock signature:

```text
31 37 43 50 58 67 77 88 100 114 129 147 166 182 203 227 255
```

3.71–3.74 do not receive guessed raw offsets.

## OLED base/runtime state

OLED uses one committed `VbeOledLutState` containing:

```text
base LUT
runtime LUT
source identity
panel type
requested transform
applied transform
```

The invariants are:

```text
raw editor/GetLut -> base
persistence       -> base
hardware injection-> runtime
runtime           -> derive(base, requested transform, panel capability)
```

Transforms never compound runtime-to-runtime. Replacement snapshots the entire previous `VbeOledLutState`, so a legal rollback restores base, runtime, source, panel and both transform truths together.

For P4/P5, the implemented RGB bias is a saturating register-code offset over every channel byte in all seven RGB triplets per row. `requested == applied` when supported. For P6/unknown, a non-neutral bias request is retained as requested, `applied` is neutral, runtime is base, and the transaction returns positive `VBE_RESULT_UNSUPPORTED` without degrading brightness ownership.

`night_mode_enabled` remains a parser-compatible request but no calibrated warm profile exists. Production therefore reports unsupported and does not fabricate warm offsets. The pure warm mechanism remains source-tested for future calibrated data; it is not a claimed v1.4 feature.

## Generic filter state

Generic domains are exactly:

```text
INVERT
AFFINE_CSC
TRANSFER
```

`VitaBrightDisplayFilterState` ABI v1 stores requested and committed parameters plus requested/committed/unsupported/failed masks. `GetParams` returns committed hardware state; `GetState` exposes the complete truth.

No generic domain is mutation-safe in pseudo-v1.4:

- **INVERT**: setter/cached state are known, but no trustworthy original-state getter. The suspected NID `0x9E3C6DC6` is `ksceDisplaySetBrightness`, not an invert getter. Mutation is unsupported rather than assuming original state zero.
- **AFFINE_CSC**: 3.65 retail analysis establishes a 0x3C `SceIftuCscParams`-shaped object, plane semantics and the legacy ABI bug, but not restoration ownership. Production performs no private IFTU write.
- **TRANSFER**: no genuine nonlinear hardware stage has been established. A 3x3 matrix is not gamma.

Unsupported requests remain requested, committed state remains neutral, the relevant unsupported mask is set, and FILTER diagnostics remain clear because capability absence is not a runtime fault.

The pure `affine_core.c` and generated CCT anchors remain in repository tests, but the affine engine is not linked into release/diagnostic SKPRX while the hardware backend is unsupported.

## Panel color-space mode

The verified panel Get/SetDisplayColorSpaceMode path remains separate from the generic filter system. Original mode is snapshotted, writes are read-back verified, and module stop restores/read-backs the original state before ownership is relinquished. Legacy `lcd_color_space_mode`, `lcd_ips_enhance` and `lcd_saturation_boost` are parser aliases for the same single capability; textual last assignment wins.

## Persistence

Normal LUT persistence requires `ACTIVE + FILE`. The transaction is:

```text
same-directory temp
-> open
-> serialize authoritative base/committed LUT
-> sync
-> close
-> rename over authoritative FILE path
```

Rename is the commit point. Temporary resources have explicit ownership. Compiled LCD state returns `VBE_RESULT_NO_FILE_SOURCE`; it never silently becomes `ur0:tai/...`.

## Stop safety

Module stop first classifies orchestration and lock state:

```text
INERT + ABSENT    -> clean stop
RUNTIME + RUNNING -> serialized stop transaction
anything else     -> STOP_FAIL
```

The runtime transaction neutralizes the generic requested filter state (there is no generic hardware mutation to restore), restores/read-backs panel color-space, cleans persistence/backend resources, then unlocks/deletes the mutex. Any unresolved hardware/resource/synchronization ownership returns `SCE_KERNEL_STOP_FAIL`; the module remains resident.

## CI proof boundary

Production-shared host tests cover parsers, source authority, config source rollback, transaction ownership, result severity, persistence, synchronization/module lifecycle, error domains, filter requested/committed truth, OLED register transform and complete OLED base/runtime state. CCT generation is reproducibility-checked and the pure affine engine is host-tested despite not being linked into production.

Structural CI only guards architecture boundaries such as “runtime reaches hardware injection” or “base is persisted”; it does not require obsolete helper spellings where the invariant has moved into a production-shared state core.

Release SKPRX, diagnostic SKPRX, generated syscall stubs and editor must all build from the same exact head with warnings treated as errors before a hardware bundle is accepted.
