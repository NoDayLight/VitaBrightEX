# VitaBrightEX pseudo-v1.4 architecture

Pseudo-v1.4 treats brightness control as the core product and every less-established display mutation as an optional capability. The correct boot failure mode is loss of an enhancement, never loss of LiveArea. During runtime mutation, however, uncertain kernel-resource ownership stops further mutation rather than attempting increasingly speculative recovery.

## Vertical contract

```text
authoritative filesystem source
    -> open-result classification
    -> authority decision
    -> production streaming parser
    -> validated candidate + explicit source identity
    -> clean ownership precondition
    -> hardware transaction
    -> committed backend state
    -> transactional mutation
    -> clean rollback OR explicit degraded ownership
    -> subsystem-owned diagnostics + truthful public result
    -> transactional persistence
    -> safe session teardown
    -> confirmed resource release
```

No layer is allowed to reinterpret another layer's failure. No Python-only grammar or test-only semantic shadow is accepted as proof.

The recurring ownership invariant is:

```text
attempt != success
```

Internal ownership changes only after the corresponding kernel/taiHEN/I/O operation confirms success.

## Boot and serialization

`module_start()` reads firmware/model, initializes status/error state and compiled-safe config defaults, then creates the state-transition mutex. Successful synchronization creation is the module's runtime-initialization commit boundary. Only after that point may authoritative config loading, brightness backend setup, panel color-space mutation or filter/invert programming begin.

If mutex creation fails, startup remains deliberately fail-open and returns `SCE_KERNEL_START_SUCCESS`. The module remains resident but `INERT`: lock lifecycle is ABSENT and no runtime/session/backend/persistence resource has been acquired. This inert outcome therefore has a corresponding clean stop path that does not enter the runtime STOPPING transaction.

No polling thread, timer, periodic file read, framebuffer interception, per-frame callback or software pixel-processing path is introduced.

One mutex serializes mutable runtime state. User writes follow:

```text
checked user copy
-> temporary candidate
-> validation
-> state lock
-> transactional change
-> commit/rollback
-> operation+unlock result composition
```

Hook callbacks themselves do not acquire the mutex.

The synchronization lifecycle remains explicit: `ABSENT`, `RUNNING`, `STOPPING`, `DEGRADED`. Ordinary runtime acquisition is legal only in RUNNING. STOPPING quiesces new user operations during module teardown. Failed unlock produces DEGRADED ownership. Mutex ID is forgotten only after confirmed delete.

Module orchestration adds only the boundary needed to mirror startup and stop: `INERT` means runtime initialization never crossed successful lock creation (or a clean stop has already released the lock); `RUNTIME` means it did. It does not duplicate mutex/backend/filter/color ownership.

## Authoritative source selection

Authority is defined by `source_authority.c` / `source_authority.h` and [`SOURCE-AUTHORITY.md`](SOURCE-AUTHORITY.md).

Only explicit OPEN-stage no-entry permits fallback:

```text
OPEN succeeds
    -> source authoritative
    -> READ/PARSE/CLOSE failure terminal

OPEN returns VBE_SCE_IO_ERROR_NOT_FOUND (0x80010002)
    -> source absent
    -> documented fallback eligible

OPEN returns any other failure
    -> terminal source I/O failure
```

`VBE_SCE_IO_ERROR_NOT_FOUND` is project-owned compatibility knowledge. Current public VitaSDK generic headers do not expose a generic `SCE_ERROR_ERRNO_ENOENT` symbol used here; the value is corroborated by Vita ecosystem implementations/usages including h-encore and Vita3K.

Config order is `ur0 -> ux0 -> compiled defaults`. LCD LUT order is `ur0 -> ux0 -> compiled safe table`. Compiled defaults are selected only when every preceding documented file is explicitly absent. OLED panel/generic search advances only on explicit absence; explicit override never falls back.

## Source identity

A LUT source is `NONE`, `FILE + path`, or `COMPILED + no path`. Source selection and hardware commit are separate layers: parsing yields candidate + identity; only successful hardware transaction commit changes the backend's committed identity.

A failed candidate B therefore cannot redirect persistence away from committed source A. Successful rollback commits A again. Dirty failure blocks persistence regardless of retained historical source metadata.

## Production parser contract

All authoritative text parsers share `text_stream.c`:

- LF accepted;
- CRLF accepted;
- CR followed by non-LF rejected;
- terminal lone CR rejected;
- CR is never deleted from inside a token.

LCD is exactly 17 unsigned decimal bytes in monotonic nondecreasing order. OLED is exactly 17 rows × 21 two-digit hex bytes. Full-line comments are streamed without a fixed physical-line buffer.

`config_parser.c` is the production config parser core. Known numerics require complete tokens; suffix garbage is rejected; extreme values saturate safely then clamp. Unknown keys and missing-`=` lines remain compatibility no-ops. Empty numeric values fail; empty `panel_lut_path` is valid. Duplicate known keys use last-valid textual occurrence. `display_color_space_mode` and `lcd_color_space_mode` are aliases for the same field and obey the same ordering rule.

Config is parsed into a temporary candidate and committed atomically.

## Backend ownership model

LCD and OLED use one shared transaction vocabulary while keeping hardware mechanics separate.

```text
CLEAN
    no backend taiHEN resource owned

ACTIVE
    full committed transaction installed

DEGRADED
    retained/uncertain ownership; no new start permitted
```

Attempt classes:

```text
TXN_OK
TXN_FAILED_CLEAN
TXN_FAILED_DIRTY
```

A start is legal only from CLEAN. A clean failure can be eligible for rollback. A dirty failure cannot. This prevents stacking a previous transaction over a partially retained candidate.

## Dependency-safe taiHEN teardown

Both brightness backends release in dependency order:

```text
power hook
-> brightness hook
-> table injection
```

Teardown stops at the first failed release. A surviving hook therefore never has its lower-level dependencies deliberately removed underneath it. Handles/references are invalidated only after confirmed release.

Failed release sets `VBE_ERR_RESOURCE_RELEASE`, ownership becomes DEGRADED, capability state is conservatively failed, and no new backend transaction begins.

## LCD transaction

PCH-2000 startup requires:

1. validated source candidate;
2. SceLcd exports by NID;
3. whitelisted firmware candidate;
4. exact runtime stock-signature match at inherited segment-0 offset;
5. table injection;
6. brightness hook;
7. ScePower hook;
8. checked current-brightness reapply;
9. LUT + source identity + ACTIVE commit.

Raw candidates remain 3.60 -> `0x1B00` and 3.65/3.67/3.68/3.69/3.70 -> `0x1B48`. 3.71–3.74 remain unsupported by raw-table injection.

Default extended table:

```text
1 3 5 8 13 20 29 41 57 76 95 116 137 161 190 220 255
```

The inactivity hook intercepts only firmware request `brightness == 1`; it suppresses the request only when the currently indexed extended value is below 25, avoiding paradoxical brightening.

## OLED transaction

PCH-1000 startup requires a whitelisted firmware family, brightness/DDB exports, successful DDB, inherited panel offset mapping, loaded-module LUT plausibility validation, complete parsed candidate, table injection, brightness/power hooks, current-brightness reapply, then LUT + source identity + panel + ACTIVE commit.

DDB low byte 4 -> `0x1AB8`, 5 -> `0x1C20`, and 6/other successfully read types -> `0x1E00`. Failed DDB never becomes an assumed default panel.

OLED bytes remain opaque panel-control data. Pseudo-v1.4 does not perform guessed white-point/RGB-bias/night-mode arithmetic.

## Replacement and rollback

Before replacement, the currently ACTIVE transaction must release completely to CLEAN. Candidate installation then runs once.

- candidate succeeds -> commit candidate LUT/source and ACTIVE;
- candidate fails cleanly -> rollback is legal only if a previous committed transaction existed;
- candidate fails dirty -> DEGRADED; rollback is forbidden;
- rollback succeeds -> previous LUT/source returns ACTIVE, requested BRIGHTNESS failure remains visible;
- rollback fails cleanly -> `VBE_ERR_LUT_ROLLBACK`, backend not ACTIVE;
- rollback fails dirty -> `VBE_ERR_RESOURCE_RELEASE`, backend DEGRADED.

Recovery failure dominates the scalar public result. The editor refreshes status/diagnostics after mutation and only says “previous committed table restored” when kernel state confirms an operational backend.

## Persistence transaction

Normal persistence is legal only for ACTIVE + FILE source identity. LCD COMPILED source returns positive `VBE_RESULT_NO_FILE_SOURCE`; Square never silently creates a guessed authoritative file.

Persistence state tracks fd ownership and temp-file ownership separately. Sequence:

```text
prepare same-directory temp
-> open
-> write exact committed LUT
-> sync
-> close
-> rename to authoritative FILE path
```

Rename is the commit point. Pre-commit failure cannot rename. fd ownership clears only after confirmed close. temp ownership clears only after confirmed remove/rename. Cleanup failure remains owned/diagnosed and cannot become success. The final source identity remains the authoritative FILE path, never the temp path.

Errors are compactly categorized as `VBE_ERR_PERSISTENCE_PREPARE`, `VBE_ERR_PERSISTENCE_COMMIT`, or `VBE_ERR_PERSISTENCE_CLEANUP`.

## Error ownership and synchronization

Per-domain slots are authoritative internal state:

- SYNC: lock lifecycle/acquire/unlock/delete;
- CONFIG: config load;
- BRIGHTNESS: backend transaction/recovery/persistence;
- COLOR_SPACE: panel color-space;
- FILTER: verified filter/invert;
- INPUT: user arguments.

`last_error/detail` remains a derived ABI-v2 compatibility summary only:

```text
SYNC > BRIGHTNESS > CONFIG > COLOR_SPACE > FILTER > INPUT
```

Runtime operations compose scalar operation and unlock results through one production-shared rule. Unlock failure dominates the scalar return while the operation's domain error remains independently stored.

`VitaBrightDiagnostics` ABI v1 remains additive.

## Unsupported filter semantics

Hardware invert is the only verified generic screen-filter mutation. Advanced CCT/gamma/contrast/brightness/panel-enhance requests return positive `VBE_RESULT_UNSUPPORTED`, leave CSC/transfer `UNSUPPORTED`, keep FILTER clear, and perform no speculative display mutation.

The private v1.3 `0x0FCBF457` path remains removed. VitaSDK's documented `ksceIftuCsc()` does not establish a persistent active-scanout matrix setter.

## Session restoration and stop safety

Panel color-space is session-owned. Original 0/1 mode is snapshotted before mutation; writes are read-back verified. Shutdown does not discard original-state metadata until current mode is confirmed restored.

Invert has a verified setter but no verified getter used here. If invert restoration setter fails, neutral state is unconfirmed and successful unload is refused.

Before beginning teardown, `module_stop()` combines module orchestration state with the authoritative lock lifecycle:

```text
INERT + ABSENT
    -> no runtime initialization ever committed (or a clean stop already completed)
    -> STOP_SUCCESS without entering STOPPING

RUNTIME + RUNNING
    -> full serialized stop transaction

any other pair, including DEGRADED
    -> STOP_FAIL
```

The inert path is safe because every teardown-requiring operation is ordered after successful lock initialization. It is intentionally not implemented by teaching the mutex state machine that ABSENT is globally unload-safe.

The runtime stop transaction is:

```text
begin STOPPING / hold serialization
-> reset filter/invert
-> restore + read back color-space
-> clean persistence temp ownership + backend taiHEN teardown
-> if any stage unresolved: checked unlock/cancel stop and return STOP_FAIL
-> otherwise unlock/delete mutex
-> set module lifecycle INERT only after confirmed delete
-> STOP_SUCCESS
```

A tiny stop accumulator answers only whether unload is safe; subsystem domains preserve detailed causes. Unconfirmed teardown leaves the plugin resident rather than allowing hooks/code pointers to outlive the module. A failed stop-cancellation unlock leaves synchronization DEGRADED and cannot take the inert path. Failed mutex deletion retains RUNTIME responsibility and the lock identity for a later safe retry.

## CI proof

`tools/validate_packaged_assets.py` byte-compares packaged assets and compiles/runs the production-shared C cores for:

- LUT parser regressions;
- config parser regressions;
- source-authority regressions;
- transaction/ownership/source-provenance/stop regressions;
- persistence sequence + ownership regressions;
- synchronization lifecycle/result regressions;
- module startup/stop lifecycle symmetry regressions;
- error-domain lifecycle/precedence regressions;
- unsupported filter policy regressions.

`tests/module_lifecycle_core_host.c` compiles the same `module_lifecycle_core.c` and `state_lock_core.c` used by production. It verifies clean inert unload after failed lock creation, normal runtime stop eligibility, DEGRADED unload rejection, failed-delete retained runtime responsibility, clean-stop return to INERT+ABSENT, repeated clean inert stop, and rejection of inconsistent module/lock pairs.

Structural scripts are tripwires, not semantic proof. They prevent obvious regressions such as split active booleans, ignored taiHEN/lock release, unverified raw firmware cases, bypassed rollback legality, fake compiled source identity, runtime mutation before the synchronization commit boundary and unsafe stop structure.

Release and diagnostic SKPRX, generated stubs, matching editor and PCH-2000 bundle build under current VitaSDK with warnings treated as errors.
